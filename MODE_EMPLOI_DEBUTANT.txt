MODE D'EMPLOI DEBUTANT - JS-C64
================================

1. A QUOI SERT JS-C64 ?
-----------------------

js-c64 permet d'ecrire un petit programme en JavaScript qui sera transforme
en code machine 6502 pour Commodore 64.

On n'ecrit pas un vrai programme JavaScript "normal".
On ecrit surtout une suite d'appels a l'objet c64.

Exemple tres simple :

import { c64 } from "js-c64";

c64.clearScreen();
c64.borderColor(c64.COLOR_BLUE);
c64.backgroundColor(c64.COLOR_BLUE);
c64.textColor(c64.COLOR_WHITE);
c64.printAt(0, 0, "HELLO C64");


2. COMMENT COMPILER UN PROGRAMME
--------------------------------

2.1 POURQUOI LA COMMANDE C64JS PEUT NE PAS ETRE RECONNUE
---------------------------------------------------------

Si vous ouvrez simplement PowerShell et tapez :

c64js build examples/hello.js -o hello.prg

Windows peut afficher un message du genre :

Le terme "c64js" n'est pas reconnu...

Ce message ne signifie pas que votre programme hello.js est mauvais.
Il signifie seulement que la commande c64js n'a pas ete installee globalement,
ou que Windows ne la trouve pas dans sa variable PATH.

Pour un debutant qui travaille directement dans le dossier du compilateur,
la methode la plus simple et la plus fiable est d'utiliser Node.js :

node .\src\cli.js build .\examples\hello.js -o .\hello.prg

Cette commande lance directement le fichier src\cli.js du projet. Elle ne
demande pas que la commande c64js soit installee globalement.


2.2 PREPARER LE PROJET UNE PREMIERE FOIS
----------------------------------------

1. Installez Node.js si ce n'est pas deja fait.

2. Dans VS Code, ouvrez le dossier complet du projet js-c64.

3. Ouvrez le terminal de VS Code :

Terminal > Nouveau terminal

4. Verifiez que le terminal se trouve bien dans le dossier du compilateur :

Get-Location

Puis verifiez que package.json est visible :

Get-ChildItem package.json

Le chemin affiche doit se terminer par le dossier du projet, par exemple :

D:\Programmation\Vibe Coding Pro\compilateur js-c64

Si vous n'etes pas dans ce dossier, utilisez cd avec le chemin entre guillemets :

cd "D:\Programmation\Vibe Coding Pro\compilateur js-c64"

Les guillemets sont indispensables lorsque le chemin contient des espaces.

5. Verifiez que Node.js et npm fonctionnent :

node -v
npm -v

Ces commandes doivent afficher des numeros de version.

6. Installez les dependances du projet. Cette operation est normalement a faire
une seule fois, puis de nouveau uniquement si package.json change :

npm install


2.3 COMPILER DEPUIS LE DOSSIER DU COMPILATEUR - METHODE RECOMMANDEE
-------------------------------------------------------------------

Pour creer un fichier PRG directement chargeable dans VICE :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.prg

Detail de la commande :

- node lance Node.js
- .\src\cli.js est le programme de compilation
- build demande une compilation
- .\examples\hello.js est le fichier source JavaScript
- -o signifie output, c'est-a-dire fichier de sortie
- .\dist\hello.prg est le fichier qui sera cree

Le compilateur cree automatiquement le dossier dist s'il n'existe pas.

Pour produire de l'assembleur 6502 lisible :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.asm --format asm

Pour produire un listing avec les adresses et les octets machine :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.lst --format lst

Pour produire un fichier binaire brut, sans en-tete PRG :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.bin --format bin

Pour produire un programme BASIC contenant des lignes DATA :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.bas --format data

Pour creer aussi une carte JSON contenant les symboles et leurs adresses :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.asm --format asm --map .\dist\hello-symbols.json

Le format est aussi deduit automatiquement de l'extension du fichier de sortie.
Par exemple, cette commande produit bien de l'assembleur :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.asm

Ecrire --format asm reste utile car cela rend la commande plus explicite.


2.4 UTILISER NPX DANS UN AUTRE PROJET
-------------------------------------

Si js-c64 est installe comme dependance dans votre propre projet, placez-vous
d'abord dans ce projet puis faites :

npm install js-c64

Vous pouvez ensuite lancer la commande locale du package avec npx :

npx c64js build .\examples\hello.js -o .\build\hello.prg

npx cherche c64js dans node_modules\.bin. Il n'est donc pas necessaire
d'installer c64js globalement.

Si le package npm n'est pas encore publie, vous pouvez l'installer depuis son
dossier local. Depuis le dossier de votre propre projet :

npm install "D:\Programmation\Vibe Coding Pro\compilateur js-c64"

Puis utilisez la meme commande npx c64js.


2.5 RENDRE LA COMMANDE C64JS DISPONIBLE PARTOUT - OPTION FACULTATIVE
-------------------------------------------------------------------

Cette methode est pratique, mais elle n'est pas obligatoire.

Ouvrez un terminal dans le dossier du compilateur js-c64, puis tapez :

npm link

npm cree alors un lien global vers le projet. Dans PowerShell, vous pouvez
verifier que la commande est maintenant visible avec :

Get-Command c64js

Puis compiler avec la commande courte :

c64js build .\examples\hello.js -o .\dist\hello.prg

Si c64js n'est toujours pas reconnu juste apres npm link, fermez puis rouvrez
le terminal. La methode avec node .\src\cli.js continuera toujours a fonctionner.


2.6 CHOISIR L'ADRESSE DE DEPART AVEC --sys
------------------------------------------

Exemple pour produire un BASIC DATA charge a l'adresse 49152 :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.bas --format data --sys 49152

Ou a l'adresse 8192 :

node .\src\cli.js build .\examples\hello.js -o .\dist\hello.bas --format data --sys 8192

Dans ces cas, le programme BASIC genere utilisera respectivement :

SYS 49152

ou :

SYS 8192

L'option --sys est surtout utile pour les formats suivants :

- BASIC DATA
- ASM
- LST
- BIN

Pour le format PRG, la version actuelle utilise normalement le cas standard
avec SYS 2064.


2.7 RESOUDRE LES ERREURS LES PLUS COURANTES
-------------------------------------------

Erreur : "c64js n'est pas reconnu"

Solution recommandee : utilisez node .\src\cli.js depuis le dossier js-c64.

Erreur : "Cannot find module ...src\cli.js"

Cause probable : le terminal n'est pas ouvert dans le dossier du compilateur.
Utilisez Get-Location, puis cd pour revenir dans le bon dossier.

Erreur : "node n'est pas reconnu"

Node.js n'est pas installe, ou son installation n'est pas dans le PATH.
Installez Node.js, puis fermez et rouvrez VS Code et son terminal.

Erreur : le fichier examples\hello.js est introuvable

Verifiez le dossier courant avec Get-Location et le fichier avec :

Get-ChildItem .\examples\hello.js

Tous les chemins de la commande sont relatifs au dossier actuellement affiche
par Get-Location.


2.8 COMPILER DIRECTEMENT UN TEXTE JS EN MEMOIRE
-----------------------------------------------

Cette nouvelle possibilite est utile si vous avez :

- un outil IA
- un emulateur
- une application Node.js

Dans ce cas, vous n'etes pas oblige d'ecrire un fichier .js sur disque.
Vous pouvez donner directement au compilateur une chaine de texte contenant
le programme JS-C64.

Exemple complet :

import { compileJsToC64Outputs } from "js-c64";

const source = `
  c64.clearScreen();
  c64.borderColor(c64.COLOR_BLUE);
  c64.backgroundColor(c64.COLOR_BLUE);
  c64.textColor(c64.COLOR_WHITE);
  c64.printAt(0, 0, "Hello, C64!");
`;

const result = await compileJsToC64Outputs(source, { sysAddress: 49152 });
console.log(result.basicText);

Ce code fait ceci :

- source contient le programme JS-C64 sous forme de texte
- compileJsToC64Outputs() compile ce texte
- sysAddress: 49152 demande un BASIC DATA avec SYS 49152
- result.basicText contient le programme BASIC final en texte simple

Autrement dit, result.basicText contient un texte du genre :

10 FORI=0TO...:READA:POKE49152+I,A:NEXT
20 SYS 49152
100 DATA ...

Important :

- cette fonction execute le texte JS dans Node.js
- il ne faut donc pas lui donner du code non fiable
- c'est tres pratique pour une IA qui genere elle-meme le code JS-C64


2.9 VERSION ENCORE PLUS SIMPLE : BASIC TEXTE DIRECT
---------------------------------------------------

Si vous voulez directement recuperer le texte BASIC sans passer par result,
vous pouvez utiliser :

import { compileJsToBasicData } from "js-c64";

const source = `
  c64.clearScreen();
  c64.borderColor(c64.COLOR_BLUE);
  c64.backgroundColor(c64.COLOR_BLUE);
  c64.textColor(c64.COLOR_WHITE);
  c64.printAt(0, 0, "Hello, C64!");
`;

const basicText = await compileJsToBasicData(source, { sysAddress: 49152 });
console.log(basicText);

Cette version est ideale si votre but est simplement :

- obtenir le texte BASIC final
- l'envoyer dans un emulateur
- ou l'afficher dans votre propre interface


3. STRUCTURE MINIMALE D'UN FICHIER
----------------------------------

Le plus simple est :

import { c64 } from "js-c64";

4. LES FONCTIONS C64 DE BASE
----------------------------

4.1 c64.clearScreen()
---------------------

Efface l'ecran du Commodore 64.

Exemple :

import { c64 } from "js-c64";

c64.clearScreen();


4.2 c64.borderColor(couleur)
----------------------------

Change la couleur du cadre de l'ecran.

Exemple :

import { c64 } from "js-c64";

c64.borderColor(c64.COLOR_RED);


4.3 c64.backgroundColor(couleur)
--------------------------------

Change la couleur du fond.

Exemple :

import { c64 } from "js-c64";

c64.backgroundColor(c64.COLOR_BLUE);


4.4 c64.textColor(couleur)
--------------------------

Definit la couleur du texte pour les prochains printAt().

Exemple :

import { c64 } from "js-c64";

c64.textColor(c64.COLOR_WHITE);
c64.printAt(0, 0, "TEXTE BLANC");


4.5 c64.print(texte)
--------------------

Affiche du texte en utilisant la routine KERNAL CHROUT.
Pratique pour un affichage simple.

Exemple :

import { c64 } from "js-c64";

c64.clearScreen();
c64.print("BONJOUR");


4.6 c64.printAt(x, y, texte)
----------------------------

Affiche un texte a la position x, y.

x = colonne
y = ligne

Exemple :

import { c64 } from "js-c64";

c64.printAt(10, 5, "AU MILIEU");


4.7 c64.printCentered(y, texte)
-------------------------------

Affiche un texte centre horizontalement sur une ligne.

Vous ne donnez que la ligne y.
La librairie calcule toute seule la bonne colonne.

Exemple :

import { c64 } from "js-c64";

c64.printCentered(10, "TEXTE AU CENTRE");


4.8 c64.waitKey()
-----------------

Attend qu'une touche du clavier soit appuyee.

Le programme reste bloque tant qu'aucune touche n'est detectee.
Ensuite il continue.

Exemple :

import { c64 } from "js-c64";

c64.printAt(0, 0, "APPUYEZ SUR UNE TOUCHE");
c64.waitKey();
c64.clearScreen();

Cette fonction est pratique pour :

- attendre que le joueur lise un message
- attendre avant de quitter un ecran
- faire une pause entre deux parties d'un programme


4.9 c64.poke(adresse, valeur)
-----------------------------

Ecrit une valeur dans une adresse memoire du C64.

Exemple :

import { c64 } from "js-c64";

c64.poke(c64.VIC_BORDER_COLOR, c64.COLOR_GREEN);


4.10 c64.peek(adresse)
----------------------

Lit une adresse memoire.
Dans la version actuelle, c'est surtout utile avec c64.poke() ou avec
de l'assembleur bas niveau.

Exemple simple :

import { c64 } from "js-c64";

c64.poke(0x0400, c64.peek(0xD020));

Cet exemple copie la couleur du border dans le premier caractere ecran.


4.10 c64.memset(adresse, valeur, longueur)
-----------------------------------------

Remplit une zone memoire avec la meme valeur.

Exemple :

import { c64 } from "js-c64";

c64.memset(c64.SCREEN_RAM, 81, 40);

Ici on remplit 40 cases ecran avec le code 81.


4.11 c64.memcpy(destination, source, longueur)
----------------------------------------------

Copie un bloc memoire vers une autre zone memoire.

Exemple :

import { c64 } from "js-c64";

c64.memcpy(0x0428, 0x0400, 40);

Ici on copie 40 octets de la premiere ligne vers la deuxieme.


4.12 c64.copyDataTo(adresse, dataRefOuNom, longueur)
----------------------------------------------------

Copie une donnee declaree avec c64.data.* vers une zone memoire.

C'est tres utile pour copier une chaine vers SCREEN_RAM, ou copier des octets
prepares a l'avance.

Exemple :

import { c64 } from "js-c64";

c64.data.screenString("titre", "BONJOUR");
c64.copyDataTo(c64.SCREEN_RAM, c64.dataRef("titre"), 8);

Ici la chaine "titre" est copiee au debut de l'ecran.


4.13 c64.memsetColor(adresse, couleur, longueur)
------------------------------------------------

Remplit une zone memoire couleur avec la meme couleur.

Exemple :

import { c64 } from "js-c64";

c64.memsetColor(c64.COLOR_RAM, c64.COLOR_YELLOW, 40);

Ici on met les 40 premieres couleurs texte en jaune.


4.14 c64.writeChar(x, y, caractere, couleur)
--------------------------------------------

Ecrit un seul caractere a une position precise.

Exemple :

import { c64 } from "js-c64";

c64.writeChar(5, 5, 81, c64.COLOR_WHITE);

Ici on ecrit le code caractere 81 en blanc.

Vous pouvez aussi donner une chaine d'un caractere :

c64.writeChar(10, 10, "*", c64.COLOR_RED);


4.15 c64.fillRect(x, y, largeur, hauteur, caractere, couleur)
--------------------------------------------------------------

Remplit un rectangle sur l'ecran texte.

Exemple :

import { c64 } from "js-c64";

c64.fillRect(0, 0, 40, 25, 32, c64.COLOR_BLUE);

Ici on remplit tout l'ecran avec des espaces bleus.

Exemple plus visible :

c64.fillRect(5, 5, 10, 4, 81, c64.COLOR_LIGHTBLUE);


4.16 c64.drawFrame(x, y, largeur, hauteur, caractere, couleur)
---------------------------------------------------------------

Dessine un cadre rectangulaire en mode texte.

Exemple :

import { c64 } from "js-c64";

c64.drawFrame(2, 2, 20, 8, 81, c64.COLOR_WHITE);

Ici on dessine un cadre blanc.


4.17 c64.clearLine(y, caractere, couleur)
-----------------------------------------

Efface ou remplit une ligne complete.

Exemple :

import { c64 } from "js-c64";

c64.clearLine(10, 32, c64.COLOR_BLUE);

Ici on remplit la ligne 10 avec des espaces bleus.


4.18 c64.screen(adresse)
------------------------

Change l'adresse de base utilisee par printAt() pour l'ecran.

Exemple :

import { c64 } from "js-c64";

c64.screen(0x0400);
c64.printAt(0, 0, "LIGNE 1");


4.19 c64.colorRam(adresse)
--------------------------

Change l'adresse de base utilisee pour les couleurs texte.

Exemple :

import { c64 } from "js-c64";

c64.colorRam(0xD800);
c64.textColor(c64.COLOR_YELLOW);
c64.printAt(0, 0, "JAUNE");


4.20 c64.sys(adresse)
---------------------

Fait un JSR vers une routine machine.

Exemple :

import { c64 } from "js-c64";

c64.sys(c64.KERNAL_CHROUT);

Remarque : pour CHROUT seul, il faut en pratique charger A avant si on veut
envoyer un caractere utile.


4.21 c64.label(nom)
-------------------

Ajoute un label dans le code genere.
C'est utile surtout avec l'assembleur bas niveau.

Exemple :

import { c64 } from "js-c64";

c64.label("debut");


4.22 c64.comment(texte)
-----------------------

Ajoute un commentaire dans la sortie assembleur/listing.

Exemple :

import { c64 } from "js-c64";

c64.comment("Preparation de l'ecran");
c64.clearScreen();


5. DONNEES ET VARIABLES
-----------------------

La version v0.2.0 ajoute une facon plus propre de manipuler :

- des donnees
- des variables
- des references symboliques

Cela evite d'ecrire trop d'adresses "magiques" a la main.


5.1 c64.data.byte(nom, valeurs)
-------------------------------

Declare une suite d'octets.

Exemple :

import { c64 } from "js-c64";

c64.data.byte("palette", [1, 2, 3, 4]);


5.2 c64.data.word(nom, valeurs)
-------------------------------

Declare une suite de mots 16 bits.

Exemple :

import { c64 } from "js-c64";

c64.data.word("positions", [0x0400, 0x0428, 0x0450]);


5.3 c64.data.string(nom, texte)
-------------------------------

Declare une chaine de texte de type PETSCII/texte KERNAL.

Exemple :

import { c64 } from "js-c64";

c64.data.string("message", "BONJOUR");


5.4 c64.data.screenString(nom, texte)
-------------------------------------

Declare une chaine deja preparee pour l'ecran texte.

Exemple :

import { c64 } from "js-c64";

c64.data.screenString("titre", "HELLO");


5.5 c64.data.length(nom)
------------------------

Renvoie la longueur de la donnee en octets.

Important :

Pour les chaines, la longueur inclut aussi l'octet de fin 0.

Exemple :

import { c64 } from "js-c64";

c64.data.screenString("titre", "HELLO");

const taille = c64.data.length("titre");


5.6 c64.dataRef(nom, longueurOptionnelle)
-----------------------------------------

Cree une reference vers une donnee declaree.

Exemple :

import { c64 } from "js-c64";

c64.data.screenString("titre", "BONJOUR");
c64.copyDataTo(c64.SCREEN_RAM, c64.dataRef("titre"), c64.data.length("titre"));

La longueur optionnelle peut etre utile si vous voulez referencer une donnee
avant sa declaration.


5.7 c64.var.byte(nom, adresseOuOptions, valeurInitiale)
-------------------------------------------------------

Declare une variable octet, comprise entre 0 et 255.

Ancienne forme avec une adresse choisie manuellement :

Exemple :

import { c64 } from "js-c64";

c64.var.byte("counter", 0xC200, 3);

Nouvelle forme recommandee pour la logique de jeu :

const counter = c64.var.byte("counter", { initial: 3 });

Le compilateur choisit alors une adresse libre dans sa zone de variables.
La reference retournee possede les operations runtime suivantes :

counter.set(10);
counter.add(2);
counter.sub(1);
counter.inc();
counter.dec();

Elle peut aussi creer des conditions avec eq(), ne(), lt(), lte(), gt() et gte().


5.8 c64.var.word(nom, adresse, valeurInitiale)
----------------------------------------------

Declare une variable mot 16 bits.

Exemple :

import { c64 } from "js-c64";

c64.var.word("playerX", 0xC210, 320);


5.9 c64.varRef(nom)
-------------------

Cree une reference vers une variable declaree.

Exemple :

import { c64 } from "js-c64";

c64.var.byte("counter", 0xC200, 0);
c64.poke(c64.varRef("counter"), 9);

Ici on ecrit 9 dans la variable "counter".

7.1 LE SON SID (V0.6.0)
-----------------------

La version actuelle de js-c64 sait deja faire :

- des petits bruitages immediats
- des notes simples
- de la musique 3 voix
- de la musique qui tourne en fond pendant des IRQ raster ou une animation

Autrement dit, on peut deja faire une petite demo sonore assez sympa.


7.1.1 c64.sid.volume(valeur)
---------------------------

Regle le volume general du SID.

La valeur va de 0 a 15.

Exemple :

import { c64 } from "js-c64";

c64.sid.volume(15);


7.1.2 c64.sid.filter(mode, cutoff, resonance)
---------------------------------------------

Active et regle le filtre SID.

Parametres :

- mode = type de filtre
- cutoff = frequence de coupure
- resonance = resonance du filtre

Valeurs utiles :

- mode peut etre :
  off
  lowpass
  bandpass
  highpass

On peut aussi combiner plusieurs modes :

- "lowpass+highpass"
- "lowpass+bandpass"

cutoff doit etre entre 0 et 2047.

resonance doit etre entre 0 et 15.

Exemple simple :

import { c64 } from "js-c64";

c64.sid.volume(15);
c64.sid.filter("lowpass", 1024, 8);

Exemple avec combinaison :

import { c64 } from "js-c64";

c64.sid.volume(10);
c64.sid.filter("lowpass+highpass", 1600, 12);

Important :

Cette fonction ecrit dans les registres SID du filtre.
Elle sert surtout a changer le caractere du son.


7.1.3 c64.sid.voice(numero)
---------------------------

Donne acces a une voix SID precise.

Le numero doit etre :

- 1
- 2
- 3

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).waveform("pulse");


7.1.4 c64.sid.voice(1).frequency(valeur)
---------------------------------------

Definit directement la frequence brute d'une voix.

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).frequency(0x1147);


7.1.5 c64.sid.freq(voix, valeur)
--------------------------------

Version plus simple pour donner une frequence.

Si la valeur est petite, la librairie la traite comme une frequence en Hertz.
Si la valeur est grande, elle la traite comme une valeur SID brute.

Exemple :

import { c64 } from "js-c64";

c64.sid.freq(1, 440);


7.1.6 c64.sid.voice(1).pulseWidth(valeur)
----------------------------------------

Regle la largeur d'impulsion pour l'onde pulse.

La valeur va de 0 a 4095.

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).waveform("pulse");
c64.sid.voice(1).pulseWidth(0x0800);


7.1.7 c64.sid.voice(1).waveform(type)
------------------------------------

Choisit la forme d'onde.

Types disponibles :

- triangle
- saw
- pulse
- noise

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).waveform("triangle");


7.1.8 c64.sid.voice(1).gate(on)
-------------------------------

Ouvre ou ferme manuellement la gate d'une voix.

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).waveform("saw");
c64.sid.voice(1).gate(true);


7.1.9 c64.sid.voice(1).attackDecay(valeur)
-----------------------------------------

Regle l'attaque et le decay.

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).attackDecay(0x11);


7.1.10 c64.sid.voice(1).sustainRelease(valeur)
---------------------------------------------

Regle le sustain et le release.

Exemple :

import { c64 } from "js-c64";

c64.sid.voice(1).sustainRelease(0xf0);


7.1.11 c64.sid.note(voix, note, duree)

7.1.13 c64.sid.playSong(songDefinition)

7.2 PREMIERE BOUCLE DE JEU RUNTIME (V0.7.0)
--------------------------------------------

Une boucle de jeu execute son bloc une seule fois par image video :

const joystick = c64.input.joystick(2);
const player = c64.sprite.create(0, {
  x: 100,
  y: 120,
  data: Array(63).fill(255),
  minX: 24,
  maxX: 320
});

c64.game.frame(() => {
  player.setVelocity(0, 0);
  c64.control.if(joystick.left(), () => player.setVelocity(-2, 0));
  c64.control.if(joystick.right(), () => player.setVelocity(2, 0));
  player.update();
});

Les directions disponibles sont :

- joystick.up()
- joystick.down()
- joystick.left()
- joystick.right()
- joystick.fire()

Pour detecter seulement la premiere frame d'un appui :

joystick.firePressed()

Pour detecter le relachement :

joystick.fireReleased()

Tres important : une condition normale JavaScript est executee par Node.js
pendant la compilation. Elle ne represente pas une decision prise par le C64.

N'ecrivez donc pas :

if (joystick.left()) {
  player.setVelocity(-2, 0);
}

Utilisez toujours c64.control.if() pour une condition runtime :

c64.control.if(joystick.left(), () => {
  player.setVelocity(-2, 0);
});

Une seule boucle c64.game.frame() est autorisee par programme. Pour le moment,
le compilateur detecte PAL ou NTSC. Avec { hz: 50 }, le jeu effectue 50 mises a
jour logiques par seconde dans les deux cas. Avec { hz: "video" }, il suit la
frequence native : 50 sur PAL et 60 sur NTSC.

La v0.7 ajoute aussi :

- c64.var.word() pour les valeurs 16 bits
- c64.var.bool() pour les etats vrai/faux
- and(), or(), xor() et toggle()
- c64.control.repeat() pour une repetition bornee
- c64.control.while() avec maxIterations obligatoire
- c64.control.routine() et c64.control.call()
- c64.input.keyboard() pour des actions clavier non bloquantes
- c64.game.init() pour l'initialisation
- c64.game.every() pour une tache periodique
- c64.table.byte() pour un tableau indexe pendant le jeu

Les variables doivent etre creees avant la boucle pour que le code de la frame
puisse garder leurs references. La configuration de l'ecran, des musiques et des
sprites peut etre regroupee dans c64.game.init().

Exemple complet :

examples/game-loop-input.js


7.3 SPRITES DE JEU, ANIMATIONS ET COLLISIONS (V0.8.0)
------------------------------------------------------

Pour un jeu, creez maintenant un sprite sous forme d'objet. Vous gardez cet
objet dans une constante et vous lui demandez ensuite de bouger, rebondir ou
tester une collision :

const pixels = Array(63).fill(255);

const player = c64.sprite.create(0, {
  x: 100,
  y: 120,
  data: pixels,
  color: c64.COLOR_YELLOW,
  minX: 24,
  maxX: 320,
  minY: 50,
  maxY: 220
});

Le premier nombre de create() est le numero materiel du sprite. Le C64 possede
8 sprites, donc les numeros valides vont de 0 a 7.

La position X n'est pas limitee a 255. player.x est une variable runtime 16
bits et le compilateur gere automatiquement le bit supplementaire dans le
registre VIC-II $D010. Une valeur comme 296 ou 320 fonctionne donc directement.

Pour deplacer le sprite avec le joystick :

const joystick = c64.input.joystick(2);

c64.game.frame(() => {
  player.setVelocity(0, 0);
  c64.control.if(joystick.left(), () => player.setVelocity(-3, 0));
  c64.control.if(joystick.right(), () => player.setVelocity(3, 0));
  player.update();
});

Les vitesses vx et vy sont signees : une valeur negative va vers la gauche ou
vers le haut. update() applique la vitesse, respecte les limites et recopie la
position dans les registres video.

Pour obtenir un rebond automatique, ajoutez bounceX: true ou bounceY: true dans
les options de create(). Les methodes reverseX() et reverseY() permettent aussi
d'inverser la direction vous-meme.

Animation avec plusieurs images :

const frames = c64.sprite.frames("hero", [imageRepos, imageMarche]);
const hero = c64.sprite.create(0, { x: 80, y: 120, frames });

hero.sequence("walk", [0, 1], { speed: 5, loop: true });
hero.play("walk");

Chaque image contient au maximum 63 octets. Le compilateur reserve et aligne
automatiquement les blocs de 64 octets demandes par le VIC-II. Plusieurs
sprites peuvent reutiliser le meme objet frames sans recopier les pixels.

Collision simple avec des rectangles invisibles (hitboxes) :

const ball = c64.sprite.create(0, {
  x: 100, y: 100, data: ballePixels,
  hitbox: { width: 8, height: 8 }
});

const paddle = c64.sprite.create(1, {
  x: 120, y: 220, data: raquettePixels,
  hitbox: { width: 24, height: 5 }
});

c64.game.frame(() => {
  ball.update();
  c64.control.if(ball.collides(paddle), () => ball.reverseY());
});

collides() effectue une collision AABB logicielle et previsible. Pour utiliser
les collisions materielles du VIC-II, il existe vicCollides() et
collidesWithBackground(). Le compilateur centralise leur lecture, car les
registres materiels de collision sont effaces lorsqu'on les lit.

Exemples complets :

examples/sprite-animate.js
examples/breakout-mini.js

Le compilateur optimise automatiquement le code genere. Si plusieurs sprites
utilisent les memes pixels, leurs donnees constantes sont partagees dans la
memoire VIC-II. Indiquez un dataAddress different pour chaque sprite si vous
voulez modifier leurs pixels separement pendant le jeu. Les collisions AABB, la synchronisation des
sprites et sid.click() utilisent aussi une routine assembleur commune lorsqu'il
y a plusieurs appels. Vous ne devez rien changer dans votre code JavaScript.


7.4 SPRITES VIRTUELS 8 A 15 ET MULTIPLEXAGE (V0.8.2)
-----------------------------------------------------

Le C64 ne possede physiquement que 8 sprites. js-c64 permet cependant de creer
16 sprites logiques, numerotes de 0 a 15 :

const top = c64.sprite.create(0, {
  x: 80, y: 70, data: pixels, color: c64.COLOR_WHITE
});

const virtuel = c64.sprite.create(8, {
  x: 180, y: 180, data: pixels, color: c64.COLOR_RED
});

c64.game.frame(() => {
  top.update();
  virtuel.update();
});

Des que vous creez le sprite 8, 9, 10, 11, 12, 13, 14 ou 15, le compilateur
active automatiquement le multiplexeur. Vous ne devez appeler aucune fonction
speciale. Les sprites 8 a 15 possedent les memes proprietes x, y, vx, vy et
active, les memes animations et les memes collisions AABB que les sprites 0 a
7.

COMMENT FONCTIONNE LE TRI AUTOMATIQUE

Les numeros 0 a 15 ne definissent plus une zone de l'ecran. Par exemple, le
sprite 8 peut etre en haut et le sprite 0 en bas :

const sprite0 = c64.sprite.create(0, { x: 80, y: 190, data: pixels });
const sprite8 = c64.sprite.create(8, { x: 180, y: 60, data: pixels });

A chaque image, le code genere effectue automatiquement les operations
suivantes :

1. il conserve uniquement les sprites actifs ;
2. il les trie du plus petit Y au plus grand Y ;
3. il attribue les huit premiers canaux materiels du VIC-II ;
4. quand un sprite est entierement termine, son canal materiel est reutilise
   pour le prochain sprite de la liste.

Un sprite normal occupe 21 lignes. Le scheduler ajoute une petite marge avant
de reutiliser son canal. Avec expandY: true, il tient compte d'une hauteur de
42 lignes. La position X et l'option expandX ne changent pas les lignes raster
occupees.

Il n'existe donc plus de separation fixe entre le haut et le bas. Un sprite
place au centre reste programme pendant toute sa hauteur. Il n'est pas coupe et
il n'est pas necessaire de le dessiner deux fois. Cela evite aussi de gaspiller
un second canal materiel pour le meme sprite.

Le tri, la copie des positions, couleurs, pointeurs et options ainsi que la
reutilisation des canaux sont realises par des routines assembleur partagees.
Le JavaScript de l'utilisateur reste simple et le PRG reste compact.

LIMITATIONS IMPORTANTES

1. Une boucle c64.game.frame() est obligatoire.

2. Tous les sprites 0 a 15 peuvent etre places librement sur X et Y et peuvent
se croiser verticalement. Leur numero n'impose aucune zone.

3. Le C64 ne peut toujours afficher que 8 sprites sur une meme ligne raster.
Si un neuvieme sprite recouvre le meme intervalle vertical, aucun canal
materiel n'est disponible : ce sprite est omis pendant cette image. Il pourra
reapparaitre automatiquement a l'image suivante si une place se libere.

4. expandY: true double la hauteur raster utilisee. Il est donc plus facile
d'atteindre la limite de 8 chevauchements avec des sprites agrandis en Y.

5. Utilisez spriteA.collides(spriteB) pour les collisions. vicCollides() et
collidesWithBackground() ne sont pas disponibles avec le multiplexage, car les
bits de collision materiels correspondent aux 8 canaux reutilises.

6. N'utilisez pas en meme temps l'ancienne API directe comme
c64.sprite.position(). Manipulez uniquement les objets retournes par
c64.sprite.create(). Le compilateur signale ce melange comme une erreur.

7. Gardez la boucle de jeu courte et bornee. Le tri et la preparation des
premiers canaux doivent etre termines avant le retour de l'image visible.

En mode multiplexe, la mise a jour logique commence automatiquement vers la
ligne raster 200. Seule la memoire logique est modifiee a ce moment : les
registres VIC-II ne sont reprogrammes qu'au vrai retour du raster en haut de
l'image. Un sprite central deja affiche ne peut donc pas etre coupe.

Exemple complet :

examples/sprite-multiplex-16.js

8.7 c64.irq.rasterLoop(ligne, fonction, options)
------------------------------------------------

Version simplifiee pour un effet raster en boucle.
Par defaut :

- elle enregistre le handler
- elle chaine vers le KERNAL
- elle installe l'IRQ

Exemple :

import { c64 } from "js-c64";

c64.irq.rasterLoop(245, () => {
  c64.asm.lda(c64.abs("color_state"));
  c64.asm.clc();
  c64.asm.adc(c64.imm(1));
  c64.asm.and(c64.imm(0x0f));
  c64.asm.sta(c64.abs("color_state"));
  c64.asm.sta(c64.abs(c64.VIC_BORDER_COLOR));
});

c64.asm.label("color_state");
c64.asm.byte(0);

Exemple avec options :

c64.irq.rasterLoop(245, () => {
  c64.borderColor(c64.COLOR_RED);
}, {
  chainToKernal: true,
  install: true,
  disableKernalTimer: false
});

12.6 Mode hires bitmap
----------------------

La version actuelle ajoute un premier support du mode bitmap hires du C64.

Fonctions disponibles :

- c64.hires.screen(adresse)
- c64.hires.bitmap(adresse)
- c64.hires.enabled()
- c64.hires.disabled()
- c64.hires.clear(couleur)
- c64.hires.point(x, y, couleur)
- c64.hires.line(x1, y1, x2, y2, couleur)
- c64.hires.rect(x, y, largeur, hauteur, couleur)
- c64.hires.fillRect(x, y, largeur, hauteur, couleur)
- c64.hires.circle(x, y, rayon, couleur)
- c64.hires.fillCircle(x, y, rayon, couleur)

Exemple simple :

import { c64 } from "js-c64";

c64.hires.screen(0x0400);
c64.hires.bitmap(0x2000);
c64.hires.enabled();
c64.hires.clear(c64.COLOR_WHITE);
c64.hires.line(10, 10, 310, 190, c64.COLOR_BLACK);
c64.hires.rect(60, 50, 200, 90, c64.COLOR_RED);
c64.hires.fillRect(90, 70, 40, 20, c64.COLOR_CYAN);
c64.hires.circle(180, 80, 24, c64.COLOR_ORANGE);
c64.hires.fillCircle(260, 140, 20, c64.COLOR_GREEN);
c64.waitKey();
c64.hires.disabled();
c64.clearScreen();

Adresses par defaut :

- memoire ecran hires : $5C00
- memoire bitmap hires : $6000

Vous pouvez les changer si besoin :

c64.hires.screen(0x5c00);
c64.hires.bitmap(0x6000);

Explication des nouvelles fonctions :

- c64.hires.enabled() active le mode hires bitmap
- c64.hires.disabled() quitte le mode hires et remet le VIC en mode texte
- c64.waitKey() attend qu'une touche soit appuyee avant de continuer

Exemple typique :

c64.hires.screen(0x0400);
c64.hires.bitmap(0x2000);
c64.hires.enabled();
c64.hires.clear(c64.COLOR_BLACK);
c64.hires.line(20, 20, 300, 180, c64.COLOR_WHITE);
c64.waitKey();
c64.hires.disabled();
c64.clearScreen();

Le c64.clearScreen() final est souvent utile pour retrouver un ecran BASIC propre.

Important a comprendre :

En hires C64 standard, la couleur n'est pas vraiment definie pour chaque pixel.
Elle est definie par bloc de 8x8 pixels.

Cela veut dire que :

- deux lignes de couleurs differentes dans le meme bloc 8x8 peuvent partager
  la meme couleur visible
- une couleur peut sembler changer par petits morceaux
- ce n'est pas forcement un bug du compilateur, c'est souvent une limite
  normale du hardware du Commodore 64
