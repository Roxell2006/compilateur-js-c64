JS-C64 — LE GUIDE DE PROGRAMMATION
==================================
Apprendre progressivement à créer des programmes C64 — version 1.1.0

Ce guide vous accompagne de l'installation de js-c64 avec npm jusqu'à la
création de jeux et de programmes en code machine pour le Commodore 64.

Vous écrivez des conditions, calculs, boucles et fonctions JavaScript ; js-c64
produit du code machine 6502. Le C64 n'exécute ni Node.js ni un interpréteur JS.

Lisez d'abord les chapitres 1 à 8, puis choisissez votre parcours : sprites,
son, dessin ou jeux avec scroll. L'assembleur et les interruptions peuvent
attendre un deuxième passage. Un bloc « Programme complet » se copie dans un
fichier .js. Les autres blocs sont des extraits à intégrer à votre programme.
Les commandes s'exécutent dans un terminal depuis le dossier du projet.

1. INSTALLER LES OUTILS
======================
Installez Node.js 18 ou supérieur, qui fournit également npm. Prévoyez un éditeur
de texte et un émulateur C64 capable de lancer un PRG, par exemple le mien en ligne: https://c64.romualdhansen.com/
Aucun assembleur externe n'est requis.
Vérifiez les outils dans un terminal :

    node --version
    npm --version

Node.js et npm servent sur votre ordinateur à installer la bibliothèque et à
compiler. Ils ne sont pas nécessaires sur le C64 qui exécutera votre programme.
Installez js-c64 dans le dossier de votre projet, comme indiqué ci-dessous.


2. CRÉER UN PROJET, COMPILER ET LANCER SON PREMIER PRG
===================================================
Depuis le dossier où vous souhaitez ranger vos projets :

    mkdir mon-jeu
    cd mon-jeu
    npm init -y
    npm pkg set type=module
    npm install js-c64@^1.1.0

npm init crée package.json, qui décrit le projet. Le réglage type=module permet
les imports JavaScript. npm install ajoute js-c64 aux dépendances et installe
une version compatible avec la 1.1.0 dans le dossier node_modules.
Créez main.js dans mon-jeu :

--- Programme complet : 01-bonjour ---
"use c64";
import { c64 } from "js-c64";

c64.screen.setup({ color: c64.COLOR_CYAN });
c64.printCentered(10, "BONJOUR LE C64 !");
c64.printAt(7, 13, "MON PREMIER PROGRAMME JS");
--- Fin du programme ---

Compilez :

    npx c64js build main.js -o dist/mon-jeu.prg

Ouvrez ce PRG avec l'autostart de votre émulateur. Il contient une adresse de
chargement et, par défaut, un lanceur BASIC. Vous pouvez aussi le transférer
sur un vrai C64 avec votre matériel habituel.

Ne lancez pas « node main.js » : c'est l'entrée du compilateur C64. Après chaque
modification, recompilez puis rechargez le nouveau PRG.

Organisation conseillée :

    mon-jeu/
      main.js
      package.json
      assets/       ressources JSON
      dist/         résultats de compilation

Pour ajouter une commande pratique :

    npm pkg set "scripts.build=c64js build main.js -o dist/mon-jeu.prg"
    npm run build

3. COMPRENDRE UN PROGRAMME JS-C64 ET LA DIRECTIVE "USE C64"
=========================================================
Commencez chaque fichier source destiné à être compilé pour le C64 par :

    "use c64";
    import { c64 } from "js-c64";

À quoi sert "use c64" ?
----------------------
Cette directive indique au compilateur js-c64 d'analyser les variables,
conditions, boucles et fonctions JavaScript pour les traduire en instructions
6502. Par exemple, « if (vies === 0) » devient un test effectué pendant
l'exécution sur le C64 ; une variable let correspond à une valeur en mémoire.

Placez-la au début du fichier, avant l'import, et conservez-la dans tous les
programmes C64 de ce guide, même les plus simples. Elle ne remplace pas l'import :
celui-ci donne accès aux fonctions c64, comme clearScreen ou sprite.create.
Elle ne lance pas non plus la compilation : utilisez « npx c64js build ».

Quand ne pas l'utiliser ?
------------------------
Ne la mettez pas dans vos scripts Node.js exécutés sur l'ordinateur, par exemple
un outil appelant compileFile pour construire un PRG (chapitre 23). Dans un
moteur JavaScript ordinaire, "use c64" n'a pas de comportement spécial : elle
ne transforme pas Node.js en émulateur et ne crée pas un environnement C64.

À la compilation, js-c64 lit les assets, réserve la mémoire et assemble le
programme. Sur le C64, les instructions produites modifient les variables,
lisent les entrées, dessinent et jouent les sons. Un JSON de votre ordinateur
n'est donc pas recherché au moment où le C64 joue. Le chargement sur disquette
C64 est une autre opération, présentée au chapitre 18.

Le langage est un sous-ensemble de JavaScript adapté au C64 :

  Disponible                       À ne pas utiliser dans le source C64
  let, const, if, else              DOM, console, API Node.js
  for, while, break, continue       classes, objets créés dynamiquement
  fonctions et return              récursion, async/await, Promise
  tableaux typés fixes             push, pop, map, filter, tableaux extensibles
  entiers 8 et 16 bits              nombres flottants

Les objets { ... } décrivent surtout des options constantes. player ou camera
sont des références à des ressources du moteur, pas des objets alloués par un
interpréteur JS. Gardez votre code C64 dans un fichier pour débuter : les imports
utilisateur ne constituent pas un système général de modules JavaScript.
Déclarez les fonctions au premier niveau. Les callbacks du moteur présentés ici
sont synchrones et sans paramètres ; utilisez des fonctions nommées ou des
flèches sans arguments.


4. ÉCRAN TEXTE, COULEURS, CARACTÈRES ET NOMBRES
============================================
L'écran texte standard contient 40 colonnes et 25 lignes : x = 0..39, y = 0..24.

    c64.screen.setup({
      mode: "text", background: c64.COLOR_BLACK,
      border: c64.COLOR_BLUE, color: c64.COLOR_WHITE, clear: true
    });

Sans options : texte, fond et bordure noirs, encre blanche, écran effacé.
Si border est omis, il reprend background. mode et clear sont constants ; les
couleurs peuvent être calculées. clear: false préserve le contenu mais configure
tout de même le mode vidéo. Installez un charset personnalisé après setup.

Les appels simples restent la bonne méthode pour une opération précise :

    c64.clearScreen();
    c64.borderColor(c64.COLOR_BLACK);
    c64.backgroundColor(c64.COLOR_BLACK);
    c64.textColor(c64.COLOR_WHITE);

Palette, avec le préfixe c64. :

  0 COLOR_BLACK       4 COLOR_VIOLET       8 COLOR_ORANGE     12 COLOR_GRAY2
  1 COLOR_WHITE       5 COLOR_GREEN        9 COLOR_BROWN      13 COLOR_LIGHTGREEN
  2 COLOR_RED         6 COLOR_BLUE        10 COLOR_LIGHTRED   14 COLOR_LIGHTBLUE
  3 COLOR_CYAN        7 COLOR_YELLOW      11 COLOR_GRAY1      15 COLOR_GRAY3

Afficher du texte et des nombres
-------------------------------
    c64.print("BONJOUR");                  à la position du curseur
    c64.printAt(2, 4, "SCORE", 7);          à une position donnée
    c64.printCentered(8, "JEU TERMINE");    centré sur une ligne
    c64.printNumber(10, 4, 123, { digits: 5, color: 1 });

Le dernier appel affiche 00123. digits est constant, de 1 à 5. Une largeur trop
petite ne conserve que les chiffres de droite. Passez une variable directement
à printNumber : la concaténation de texte et de nombres calculés n'est pas
une chaîne C64. Préférez des textes en majuscules sans accents : le jeu de
caractères C64 n'est pas Unicode.

Caractères et zones
-------------------
    c64.writeChar(10, 10, 81, c64.COLOR_YELLOW);
    c64.fillRect(2, 5, 12, 4, 32, c64.COLOR_BLUE);
    c64.drawFrame(1, 4, 14, 6, 81, c64.COLOR_CYAN);
    c64.clearLine(20);

fillRect remplit ; drawFrame dessine un contour. Les dimensions sont en cases,
pas en pixels. clearLine accepte aussi caractère et couleur. Le remplissage
utilise par défaut l'espace, code 32 ; le cadre utilise le caractère 81.
Un code écran n'est pas un code ASCII : A vaut 1, les chiffres commencent à 48.
writeChar accepte aussi un caractère littéral. Gardez les zones dans l'écran :
une forme hors limites n'est pas automatiquement découpée à son bord.

--- Programme complet : 02-compteur ---
"use c64";
import { c64 } from "js-c64";

c64.screen.setup({ border: c64.COLOR_BLUE });
c64.drawFrame(5, 5, 30, 12, 81, c64.COLOR_CYAN);
c64.printAt(8, 7, "TABLE DE MULTIPLICATION");
for (let i = 0; i < 5; i++) {
  c64.printNumber(12, 10 + i, i, { digits: 1 });
  c64.printNumber(20, 10 + i, i * 3, { digits: 2 });
}
--- Fin du programme ---


5. VARIABLES, CALCULS, CONDITIONS ET BOUCLES
==========================================
    let vies = 3;                  entier non signé 8 bits : 0..255
    let termine = false;           booléen
    let position = c64.word(300);   entier non signé 16 bits : 0..65535
    const vitesse = 2;             constante

Une petite valeur numérique initialise normalement un octet. Écrivez c64.word
pour une plage dépassant 255 ; let position = 300 est refusé sans cette largeur.
Les calculs débordent : sur un octet, 255 + 1 donne 0. Élargissez AVANT le calcul :

    let petit = 255;
    let grand = c64.word(petit) + 1;

c64.byte conserve l'octet bas. word ne récupère pas les bits déjà perdus dans un
calcul. Les vitesses de sprites/entités peuvent être négatives selon leurs API,
mais les comparaisons JavaScript restent non signées. Ne testez pas leur sens
avec vitesse < 0 ; gardez par exemple un booléen facingLeft.

    score += 10;
    vies--;
    couleur = (couleur + 1) & 15;
    if (vies === 0) {
      termine = true;
    } else if (score >= 100 && !termine) {
      c64.borderColor(c64.COLOR_GREEN);
    }

Opérateurs : +, -, &, |, ^, incréments/décréments, affectations composées ;
==, !=, ===, !==, <, <=, >, >= ; !, &&, ||. Les opérateurs logiques court-circuitent
leur deuxième opérande. Le ternaire fonctionne avec les valeurs scalaires :

    let couleur = termine ? c64.COLOR_RED : c64.COLOR_GREEN;

La multiplication par une constante de 0 à 255 est disponible, ainsi que les
décalages d'un nombre constant de 0 à 15 bits. Les expressions constantes sont
simplifiées. La multiplication de deux variables, la division et le modulo
dynamiques ne sont pas proposés. Pour les puissances de deux, >> et & peuvent
exprimer certains calculs entiers.

Boucles
-------
    for (let x = 0; x < 40; x++) {
      c64.writeChar(x, 12, 81, c64.COLOR_WHITE);
    }

    while (vies > 0) {
      vies--;
      if (vies === 1) break;
    }

break quitte la boucle ; continue passe à l'itération suivante. La condition
doit pouvoir devenir fausse. Un compteur byte ne peut pas atteindre 256 :
utilisez un word pour parcourir 256 éléments. Une longue boucle bloque le reste
de la frame ; pour animer un jeu, employez game.run, pas un while infini.


6. FONCTIONS, TABLEAUX ET GRILLES
================================
    function dessinerCase(x, y, couleur) {
      c64.writeChar(x, y, 81, couleur);
    }

Les fonctions acceptent nombres, booléens, références de ressources/tableaux et
texte constant. Les scalaires sont passés par valeur ; les références désignent
les mêmes données. Un retour est numérique ou booléen ; une fonction utilisée
comme valeur doit retourner une valeur sur tous les chemins. Pas de récursion.

Tableaux fixes
--------------
    const cases = new Uint8Array(200);
    const positions = new Uint16Array([40, 160, 300]);
    cases[3] = 1;
    cases[3]++;
    let contenu = cases[3];
    cases.fill(0);

Le tableau est réservé à la compilation, avec 1 à 256 éléments. Uint8Array
stocke des octets, Uint16Array des mots. Les valeurs initiales sont constantes.
.length donne la taille ; fill remplit tout le tableau, sans variante début/fin.
Un indice constant invalide provoque une erreur ; un indice dynamique hors
limites donne zéro en lecture et ignore l'écriture.
Un tableau ordinaire [ ... ] sert à une configuration constante. Pour des
données modifiables et un indice variable, choisissez un tableau typé.

--- Programme complet : 03-grille ---
"use c64";
import { c64 } from "js-c64";

const cases = new Uint8Array(100);
function index(x, y) {
  return y * 10 + x;
}
function dessiner() {
  for (let y = 0; y < 10; y++) {
    for (let x = 0; x < 10; x++) {
      let couleur = cases[index(x, y)] === 0 ? 6 : 7;
      c64.writeChar(x + 15, y + 7, 81, couleur);
    }
  }
}
c64.screen.setup();
cases.fill(0);
cases[index(4, 4)] = 1;
cases[index(5, 4)] = 1;
dessiner();
--- Fin du programme ---

Au-delà de 255, les indices intermédiaires doivent être calculés sur 16 bits.
La limite de 256 éléments par tableau reste applicable : découpez une grande
grille ou utilisez les maps du moteur. Réinitialisez vos tableaux au début
d'une nouvelle partie : changer de scène ne recharge pas leurs données initiales.

7. BOUCLE DE JEU, CLAVIER, JOYSTICK ET TEMPORISATION
=================================================
Structure recommandée :

    function init() { ... }
    function update() { ... }
    c64.game.run({ init, update });

init s'exécute une fois ; update à chaque étape logique. La cadence par défaut
est { hz: 50 } ; le moteur adapte les étapes au NTSC. { hz: "video" } suit chaque
image vidéo. Cela ne rend pas instantané un calcul trop long : respectez le
budget de la machine. rasterLine règle le point de synchronisation.
Déclarez les ressources fixes hors d'update ; dessinez le décor permanent dans
init, puis ne redessinez que ce qui change.

Joystick
--------
    const joystick = c64.input.joystick(2);

  left(), right(), up(), down(), fire()       direction/bouton maintenu
  leftPressed(), firePressed(), etc.          nouvel appui
  leftReleased(), fireReleased(), etc.        relâchement

Employez ces appels dans les conditions de la frame. Le moteur capture les
entrées pour fournir un état cohérent. Le port 2 est pratique pour débuter.

Clavier
-------
    const keys = c64.input.keyboard({
      saut: c64.KEY_SPACE, valider: c64.KEY_RETURN, aide: c64.KEY_F1
    });

  keys.saut.held()       maintenue
  keys.saut.pressed()    nouvel appui
  keys.saut.released()   relâchement

c64.waitKey() est bloquant. Réservez-le aux programmes séquentiels ; dans un
jeu, pressed() permet aux animations et à la musique de continuer.

--- Programme complet : 04-clavier ---
"use c64";
import { c64 } from "js-c64";

const keys = c64.input.keyboard({ action: c64.KEY_SPACE });
let secondes = 0;
function init() {
  c64.screen.setup();
  c64.printAt(2, 8, "ESPACE : BORDURE JAUNE");
}
function compter() {
  secondes++;
  c64.printNumber(18, 12, secondes, { digits: 3 });
}
function update() {
  if (keys.action.held()) c64.borderColor(c64.COLOR_YELLOW);
  else c64.borderColor(c64.COLOR_BLACK);
  c64.game.every(50, compter);
}
c64.game.run({ init, update });
--- Fin du programme ---

--- Programme complet : 04-deplacement ---
"use c64";
import { c64 } from "js-c64";

const joystick = c64.input.joystick(2);
let x = 20;
let y = 12;
function init() {
  c64.screen.setup();
  c64.printAt(2, 2, "BOUGEZ AVEC LE JOYSTICK 2");
  c64.writeChar(x, y, 81, c64.COLOR_YELLOW);
}
function update() {
  c64.writeChar(x, y, 32);
  if (joystick.left() && x > 0) x--;
  if (joystick.right() && x < 39) x++;
  if (joystick.up() && y > 4) y--;
  if (joystick.down() && y < 24) y++;
  c64.writeChar(x, y, 81, c64.COLOR_YELLOW);
}
c64.game.run({ init, update });
--- Fin du programme ---

Pour appeler une fonction moins souvent, dans update :

    c64.game.every(25, clignoter);

clignoter doit être définie dans le programme. L'intervalle est constant,
1..255 étapes atteignant cet appel. À 50 Hz, 25 étapes font une demi-seconde si
l'appel est exécuté à chaque étape. Une condition qui saute l'appel met son
compteur en pause. game.init et game.frame existent aussi pour composer les
briques séparément ; game.run suffit normalement. Une seule boucle principale.


8. SCORES, HASARD ET SCÈNES
==========================
Compteurs décimaux
------------------
    const score = c64.game.score({ digits: 5 });
    const vies = c64.game.lives({ initial: 3 });
    const temps = c64.game.counter("temps", { digits: 3, initial: 120 });
    score.set(0);
    score.add(100);
    score.inc();
    vies.dec();
    temps.sub(10);
    score.draw(30, 1, { color: c64.COLOR_YELLOW });

set/add/sub/inc/dec modifient le compteur ; draw l'affiche. Le résultat boucle
à la capacité décimale choisie : décrémenter 000 donne 999 pour trois chiffres.
Pour décider si la partie est terminée, gardez au besoin une variable numérique
de jeu séparée. Ne supposez pas qu'un compteur décimal est une variable JS.

Hasard reproductible
--------------------
    let tirage = 0;
    c64.random.seed(42);
    c64.random.range(tirage, 6);

range écrit dans tirage un résultat de 0 à 5 : ce n'est pas une fonction qui
renvoie un nombre. byte(tirage) produit un octet. Le maximum de range est
constant, de 1 à 256 ; la graine est constante, de 1 à 255. La même graine
reproduit la même suite, ce qui aide à déboguer.

--- Programme complet : 05-hasard-score ---
"use c64";
import { c64 } from "js-c64";

const joystick = c64.input.joystick(2);
const score = c64.game.score({ digits: 5 });
let tirage = 0;
function init() {
  c64.screen.setup();
  c64.random.seed(42);
  c64.printCentered(8, "FEU : AJOUTER UN DE AU SCORE");
  score.draw(17, 12);
}
function update() {
  if (joystick.firePressed()) {
    c64.random.range(tirage, 6);
    tirage++;
    score.add(tirage);
    score.draw(17, 12);
  }
}
c64.game.run({ init, update });
--- Fin du programme ---

Scènes
------
Quatre noms fixes : "title", "game", "pause", "gameOver". Chaque scène propose
enter, update et exit. Déclarez-les, puis utilisez game.start à la place de
game.run. game.go demande une transition appliquée entre les étapes ; game.is
permet un test. Les noms ne sont pas des chaînes calculées dynamiquement.

--- Programme complet : 05-scenes ---
"use c64";
import { c64 } from "js-c64";

const joystick = c64.input.joystick(2);
let total = 0;
function titre() {
  c64.screen.setup();
  c64.printCentered(10, "FEU POUR JOUER");
}
function attendre() {
  if (joystick.firePressed()) c64.game.go("game");
}
function commencer() {
  total = 0;
  c64.screen.setup();
  c64.printAt(2, 4, "FEU : +1 / BAS : TERMINER");
}
function jouer() {
  if (joystick.firePressed()) total++;
  c64.printNumber(18, 12, total, { digits: 3 });
  if (joystick.downPressed()) c64.game.go("gameOver");
}
function resultat() {
  c64.screen.setup();
  c64.printCentered(10, "PARTIE TERMINEE");
  c64.printNumber(18, 12, total, { digits: 3 });
  c64.printCentered(15, "FEU POUR REJOUER");
}
c64.game.scene("title", { enter: titre, update: attendre });
c64.game.scene("game", { enter: commencer, update: jouer });
c64.game.scene("gameOver", { enter: resultat, update: attendre });
c64.game.start("title");
--- Fin du programme ---

Pour une pause, conservez les données de la partie : ne les réinitialisez pas
systématiquement dans enter si game est aussi utilisé pour reprendre.


9. MÉMOIRE, DONNÉES ET PLACEMENT DU PROGRAMME
===========================================
Un petit jeu peut laisser le compilateur réserver variables et temporaires.
Les accès explicites deviennent utiles pour le matériel ou une routine machine.
Le C64 a 65536 adresses ; selon sa configuration, elles désignent RAM, ROM ou
registres. Consultez le rapport mémoire avant de choisir une zone manuellement.

    c64.poke(0xd020, c64.COLOR_RED);
    c64.memset(0x0400, 32, 40);
    c64.memsetColor(0xd800, c64.COLOR_WHITE, 40);
    c64.memcpy(0x0428, 0x0400, 40);

poke écrit un octet ; memset remplit ; memcpy reçoit destination, source,
longueur. Ces primitives de bloc utilisent des longueurs sur un octet : restez
entre 1 et 255. Utilisez des blocs successifs ou les fonctions spécialisées
pour un écran entier. Évitez les copies recouvrantes : ce n'est pas memmove.

Particularité bas niveau : peek produit un descripteur de lecture, pas un
nombre JavaScript utilisable dans tous les calculs. Cet usage est prévu :

    c64.poke(0x0400, c64.peek(0x0401));

N'écrivez pas let valeur = c64.peek(...) en supposant un retour numérique
ordinaire. Pour un accès matériel plus complexe, utilisez l'assembleur.

Données embarquées
------------------
    c64.data.byte("motif", [1, 2, 3, 4]);
    const motif = c64.dataRef("motif");
    c64.copyDataTo(0x0400, motif, 4);

data.byte/word stockent octets/mots. data.string et screenString ajoutent un
zéro terminal avec des encodages différents. Les noms doivent être uniques.
dataRef retrouve une référence nommée ; copyDataTo copie vers l'adresse choisie.
data.length(nom) fournit la taille en octets, y compris le zéro terminal des
chaînes. Les déclarations data ne renvoient pas directement une référence.
Pour des données de jeu modifiables, préférez les tableaux typés.

--- Programme complet : 06-memoire ---
"use c64";
import { c64 } from "js-c64";

c64.screen.setup();
c64.data.byte("lettres", [1, 2, 3, 4]);
c64.copyDataTo(0x0400, c64.dataRef("lettres"), c64.data.length("lettres"));
c64.memset(0x0428, 81, 40);
c64.memsetColor(0xd828, c64.COLOR_YELLOW, 40);
c64.memcpy(0x0450, 0x0428, 40);
c64.poke(0x0478, c64.peek(0x0400));
--- Fin du programme ---

Placement
---------
Le code démarre normalement à $0810, soit 2064. Pour choisir un autre placement :

    c64.program.start(0x4000);

Le PRG conserve un lanceur adapté qui met en place le code. Ce choix doit être
cohérent avec les assets ; il ne crée pas de mémoire supplémentaire. Les variables
du programme occupent une zone dédiée, notamment $C100–$C2FF : ne réutilisez pas
ces adresses sans vérifier les réservations du compilateur.
screen(adresse) et colorRam(adresse) changent les bases des helpers texte.
Une organisation vidéo personnalisée demande aussi une configuration cohérente
de la banque et des registres VIC-II.


10. INSÉRER DE L'ASSEMBLEUR 6502
==============================
L'assembleur peut rester dans le même fichier source JavaScript. Réservez-le aux routines
dont vous comprenez les effets sur registres, drapeaux et mémoire.

--- Programme complet : 06-assembleur ---
"use c64";
import { c64 } from "js-c64";

c64.screen.setup();
c64.printAt(0, 2, "UNE LIGNE ECRITE EN ASSEMBLEUR");
c64.asm.ldx(c64.imm(0));
c64.asm.label("ligne_asm");
c64.asm.lda(c64.imm(81));
c64.asm.sta(c64.absx(0x0400));
c64.asm.inx();
c64.asm.cpx(c64.imm(40));
c64.asm.bne(c64.rel("ligne_asm"));
--- Fin du programme ---

X compte de 0 à 39 ; A contient le caractère ; STA écrit à $0400 + X.
BNE revient au label tant que la comparaison avec 40 n'est pas égale.

Modes d'adressage
-----------------
  imm(10)         immédiat #10
  immLo(label)    octet bas de l'adresse d'un label
  immHi(label)    octet haut
  zp(0xfb)        page zéro
  zpx / zpy       page zéro indexée
  abs(0x0400)     absolu
  absx / absy     absolu indexé par X/Y
  ind(adresse)    indirect, notamment pour JMP
  indx(adresse)   indirect indexé avant lecture du pointeur
  indy(adresse)   pointeur indirect puis ajout de Y
  rel(label)     branchement relatif
  acc()          accumulateur
  impl()         implicite

Préfixez ces helpers avec c64. Chaque instruction n'accepte que les modes
prévus par le 6502. Un branchement relatif atteint -128..127 octets ; pour aller
plus loin, inversez le test puis utilisez JMP.

Instructions c64.asm
-------------------
  Chargement/transfert : lda ldx ldy sta stx sty tax tay tsx txa txs tya
  Calcul/logique      : adc sbc and ora eor asl lsr rol ror inc dec
  Compteurs/tests     : inx iny dex dey cmp cpx cpy bit
  Branchements        : bcc bcs beq bmi bne bpl bvc bvs jmp jsr rts
  Pile/interruption   : pha php pla plp brk rti
  Drapeaux/autres     : clc cld cli clv sec sed sei nop

Avant une addition indépendante avec ADC, utilisez CLC ; avant une soustraction
avec SBC, utilisez SEC. Le compilateur gère cela pour les expressions JavaScript.
asm.label/comment nomment et annotent. asm.byte émet des octets bruts : ne placez
pas des données sur un chemin exécuté. c64.label/comment existent également.
c64.sys(adresse) appelle une routine externe qui doit revenir par RTS.

Les noms des variables déclarées avec let ne sont pas des labels publics stables. Pour une
interopérabilité explicite, var.byte/word/bool réservent une variable nommée,
éventuellement à adresse fixe, et varRef la retrouve. Ce cas spécialisé ne
remplace pas les let habituels. Ne pointez pas arbitrairement dans les temporaires.
Le moteur utilise A/X/Y et de la page zéro, notamment $FB–$FE pour certaines
opérations. Ne supposez pas leur conservation par un appel c64. Ne laissez pas
le mode décimal SED actif à l'entrée du code compilé. N'ajoutez pas RTS au milieu
d'une fonction JavaScript : laissez le compilateur gérer ses retours.


11. SPRITES : CRÉATION, MOUVEMENT, ANIMATION ET COLLISIONS
=======================================================
Le VIC-II fournit huit sprites matériels. Un sprite monochrome mesure 24 × 21
pixels ; un multicolore utilise 12 × 21 points plus larges. Une image contient
63 octets, rangés dans un bloc aligné sur 64 octets.
Pour cet exemple, copiez le fichier fourni avec le paquet :
node_modules/js-c64/examples/assets/v10-hero.sprite.json
vers assets/v10-hero.sprite.json dans votre projet.

--- Programme complet : 07-sprite ---
"use c64";
import { c64 } from "js-c64";

const dessin = c64.assets.loadSprite("assets/v10-hero.sprite.json");
const joystick = c64.input.joystick(2);
const player = c64.sprite.create(0, {
  x: 160, y: 120, frames: dessin.framesRef, color: c64.COLOR_YELLOW
});
function init() {
  c64.screen.setup();
  c64.printAt(2, 2, "JOYSTICK 2 : DEPLACEMENT");
}
function update() {
  if (joystick.left() && player.x > 24) player.x -= 2;
  if (joystick.right() && player.x < 320) player.x += 2;
  if (joystick.up() && player.y > 50) player.y -= 2;
  if (joystick.down() && player.y < 220) player.y += 2;
  player.color(joystick.fire() ? c64.COLOR_CYAN : c64.COLOR_YELLOW);
  player.sync();
}
c64.game.run({ init, update });
--- Fin du programme ---

Ce sont les coordonnées VIC-II avec le décalage de la zone visible, pas les
coordonnées texte/HR. x va matériellement de 0 à 511 ; y de 0 à 255.

Deux manières de déplacer
------------------------
  Manuel : modifiez player.x/y, puis sync() publie la position.
  Moteur : configurez vx/vy et les bornes, puis update() applique mouvement,
           limites/rebonds, animation et synchronisation.

Évitez d'ajouter involontairement les deux mouvements. Les vitesses négatives
ont ici une interprétation signée propre au moteur.

Options de création
-------------------
  x/y ; vx/vy ; active ; color ; frames ou data/dataAddress
  multicolor ; expandX/expandY ; priority
  minX/maxX/minY/maxY ; bounceX/bounceY
  hitbox: { offsetX, offsetY, width, height }

Méthodes : setPosition(x,y), setVelocity(vx,vy),
setBounds(minX,maxX,minY,maxY,{ bounceX, bounceY }), reverseX/Y(),
update(), sync(), enable(), disable(), color(valeur), multicolor(bool),
expandX/Y(bool), priority(bool). La hitbox ajuste le rectangle de collision.
sharedColor1 et sharedColor2, sur c64.sprite, règlent les deux couleurs communes
aux sprites multicolores ; elles ne sont pas indépendantes pour chaque sprite.

Animation et collisions
------------------------
Pour un asset d'au moins deux images, hors de la boucle :

    player.sequence("marche", [0, 1], { speed: 6, loop: true });
    player.play("marche");

speed règle les mises à jour par image. Rappeler la même séquence ne sert pas
à la recommencer. pauseAnimation/resumeAnimation la suspendent/reprennent.
Appelez update pour la faire avancer. Les noms sont constants : pour en choisir
un, utilisez if/else, pas une chaîne dynamique issue d'un ternaire.

    if (player.collides(enemy)) { ... }
    if (player.vicCollides(enemy)) { ... }
    if (player.collidesWithBackground()) { ... }

collides teste les rectangles logiciels. vicCollides et la collision avec le
fond utilisent les informations matérielles. Pour la physique du terrain,
utilisez les entités de map.

Plus de huit sprites et données personnalisées
---------------------------------------------
create accepte les indices logiques 0..15 ; 8..15 sollicitent le multiplexeur
avec la boucle de jeu. Il réutilise les sprites à différentes hauteurs, pas
seize sprites sur une même ligne raster. L'agrandissement vertical augmente
les contraintes. N'ajoutez pas un autre pilote qui modifie les mêmes registres.
sprite.frames(nom, tableauxDe63Octets, { address }) construit une banque sans
JSON ; assets.defineSprite accepte une description constante selon le schéma.
Un asset JSON édité graphiquement reste souvent plus facile à maintenir.

12. SONS ET MUSIQUE : LE SID
===========================
Le SID a trois voix. Commencez par les effets non bloquants :

    c64.sid.volume(12);
    c64.sid.reserveSfxVoice(3);
    c64.sid.pickup();

Effets : beep(), click(), explosion(), laser(), pickup(), noise(duree).
La durée de noise est en ticks de 1/50 seconde ; 0 devient un tick. Un nouvel
effet remplace celui en cours sur la voix réservée. Le moteur audio avance par
IRQ avec adaptation PAL/NTSC. Utilisez firePressed(), pas fire(), si vous ne
voulez pas redéclencher un son à chaque frame de l'appui.

--- Programme complet : 08-musique ---
"use c64";
import { c64 } from "js-c64";

const joystick = c64.input.joystick(2);
const lead = c64.sid.instrument("lead", {
  waveform: "pulse", pulseWidth: 0x0800,
  attackDecay: 0x11, sustainRelease: 0x98
});
const melody = c64.sid.pattern("melody", ["C4", "E4", "G4", "E4"]);
const silence = c64.sid.pattern("silence", [{ rest: true, duration: 4 }]);
c64.sid.reserveSfxVoice(3);
c64.sid.volume(12);
c64.sid.playSong({
  tempo: 5, loop: true,
  instruments: [lead, null, null],
  voices: [melody.repeat(2), silence.repeat(2), silence.repeat(2)]
});
function init() {
  c64.screen.setup();
  c64.printCentered(10, "FEU : BRUITAGE");
}
function update() {
  if (joystick.firePressed()) c64.sid.pickup();
  if (joystick.upPressed()) c64.sid.pauseSong();
  if (joystick.downPressed()) c64.sid.resumeSong();
}
c64.game.run({ init, update });
--- Fin du programme ---

Une chanson décrit trois voix et leurs instruments. Les patterns contiennent
noms de notes, { note: "C4", duration: 2 } ou { rest: true, duration: 2 }.
repeat développe une répétition à la compilation. tempo règle l'unité musicale
en ticks à 50 Hz. La voix réservée aux effets doit rester disponible.
pauseSong/resumeSong/stopSong contrôlent le lecteur. fadeSong(volume, intervalle)
modifie le volume global, partagé avec les effets. installPlayer(ligne) permet
un réglage explicite de la ligne raster du lecteur.

Contrôle direct d'une voix
-------------------------
    const voix = c64.sid.voice(1);
    voix.waveform("triangle");
    voix.frequency(4000);
    voix.attackDecay(0x12);
    voix.sustainRelease(0x88);
    voix.gate(true);

frequency et sid.freq utilisent la même convention : un entier supérieur à
2048 et inférieur ou égal à 65535 est une valeur brute de registre ; les autres
valeurs sont converties depuis des Hz avec l'horloge PAL. Pour une mélodie,
préférez des noms de notes afin d'éviter cette ambiguïté d'unité. pulseWidth
accepte 0..4095 ; waveform choisit triangle, saw, pulse, noise. attackDecay
combine attaque/décroissance en deux demi-octets ; sustainRelease combine
maintien/relâchement. gate(false) commence le relâchement. Ces réglages bas
niveau utilisent des paramètres de configuration constants.
sid.filter(mode, cutoff, resonance) règle le filtre : off, lowpass, highpass,
bandpass ou combinaisons, coupure 0..2047, résonance 0..15. volume vaut 0..15.
sid.note(voix, nom, durée), sid.freq et sid.rest sont des outils directs : les
attentes note/rest conviennent aux essais séquentiels ; préférez playSong et
les effets non bloquants pendant un jeu. Ne pilotez pas la même voix depuis
le lecteur et une routine indépendante sans prévoir leur coordination.


13. DESSIN HAUTE RÉSOLUTION : LE MODE HR
======================================
Le bitmap HR mesure 320 × 200 pixels : x = 0..319, y = 0..199. Une abscisse
variable dépassant 255 doit être un word.

--- Programme complet : 09-haute-resolution ---
"use c64";
import { c64 } from "js-c64";

c64.screen.setup({ mode: "hires", background: c64.COLOR_BLACK });
for (let i = 0; i < 5; i++) {
  let x = c64.word(i) * 60 + 10;
  let taille = 16 + i * 3;
  let couleur = i + 1;
  c64.hires.rect(x, 20, taille, taille, couleur);
  c64.hires.fillRect(x, 65, taille, taille, couleur);
  c64.hires.circle(x + 16, 125, 6 + i * 2, couleur);
  c64.hires.fillCircle(x + 16, 170, 6 + i * 2, couleur);
}
--- Fin du programme ---

Outils
------
  hires.point(x, y, couleur)
  hires.line(x1, y1, x2, y2, couleur)
  hires.rect(x, y, largeur, hauteur, couleur)
  hires.fillRect(x, y, largeur, hauteur, couleur)
  hires.circle(x, y, rayon, couleur)
  hires.fillCircle(x, y, rayon, couleur)
  hires.clear(couleur)

Préfixez par c64. Les coordonnées, dimensions et couleurs peuvent être calculées.
Une forme dynamique hors limites peut être ignorée entièrement ; pas de clipping
général. Le centre d'un cercle doit rester à une distance du bord au moins égale
à son rayon.

Couleurs par cellule
--------------------
Le bitmap a un bit par pixel, pas une couleur indépendante par point. Chaque
cellule de 8 × 8 pixels partage un premier plan et un fond. Dessiner une autre
couleur dans la même cellule peut recolorer des pixels déjà allumés : c'est
une contrainte matérielle, même quand le dessin géométrique est correct.
clear(0) efface en noir ; clear() sans argument utilise le blanc. Effacer le
bitmap à chaque frame coûte cher. Dessinez seulement quand quelque chose change,
comme dans natural-hires-interactive.js.

Par défaut, écran HR à $5C00 et bitmap à $6000. hires.screen/bitmap changent ces
adresses : écran aligné sur 1 Ko, bitmap sur 8 Ko, dans une banque vidéo cohérente
de 16 Ko. Vérifiez les autres réservations. hires.enabled/disabled changent le
mode. screen.setup({ mode: "text" }) prépare le retour au texte standard ;
réinstallez ensuite un éventuel charset personnalisé. Ce chapitre ne décrit
pas une API de dessin bitmap multicolore.


14. RASTER ET INTERRUPTIONS
==========================
Le raster est la ligne affichée par le VIC-II. Une interruption raster exécute
une courte routine à une ligne choisie, par exemple pour changer une couleur.

--- Programme complet : 10-raster ---
"use c64";
import { c64 } from "js-c64";

function init() {
  c64.screen.setup();
  c64.printCentered(12, "DEUX COULEURS DE BORDURE");
}
function update() {
}
c64.irq.raster(60, () => c64.borderColor(c64.COLOR_CYAN));
c64.irq.raster(160, () => c64.borderColor(c64.COLOR_BLUE));
c64.irq.install();
c64.game.run({ init, update });
--- Fin du programme ---

raster déclare l'action ; install installe le gestionnaire. Celui-ci acquitte
les interruptions prises en charge. irq.ack est un outil bas niveau, pas un
appel à ajouter systématiquement dans chaque callback.
PAL a 312 lignes, NTSC moins : commencez par des lignes inférieures à 256 et
vérifiez chaque standard ciblé. Le nombre de cycles par ligne reste limité.

  irq.chainToKernal()       enchaînement vers les services du KERNAL
  irq.disableKernalTimer()  désactivation de l'IRQ du timer KERNAL
  irq.enableKernalTimer()   réactivation du timer

irq.rasterLoop(ligne, callback, options) regroupe déclaration et installation.
Options : disableKernalTimer, chainToKernal, install. Les deux dernières sont
activées par défaut ; la désactivation du timer est explicite. Couper les
services KERNAL affecte leur clavier et leur horloge ; les entrées directes du
moteur ne dépendent pas toutes de ces services.

Audio, multiplexeur et scroll utilisent le dispatcher commun. Déclarez vos
effets avec irq.raster au lieu de remplacer le vecteur IRQ. Gardez les handlers
courts ; dessinez les grandes formes et calculez le jeu dans update.
Les fonctions JavaScript utilisent des paramètres/variables statiques et ne
sont pas réentrantes : le compilateur refuse les usages incompatibles entre
boucle principale et IRQ. Les écritures de word ne sont pas atomiques sur 6502.
Évitez aussi que deux routines concurrentes utilisent les mêmes temporaires
de dessin. Une synchronisation avancée demande une conception explicite.


15. PRÉPARER LES GRAPHISMES, MAPS ET OBJETS
========================================
Le dépôt inclut « studio graphique/index.html », à ouvrir dans un navigateur.
Ce dossier n'est pas livré dans le paquet npm. Préparez et exportez vos sprites
et maps en JSON ; les schémas du dossier schemas décrivent les formats.
assets.defineMap accepte aussi une description constante, mais loadMap garde
le programme plus court.

Ne confondez pas les unités :
  caractère : 8 × 8 pixels ;
  tuile     : assemblage de caractères, selon tileWidth/tileHeight ;
  monde     : positions des entités, en pixels.
Une tuile peut mesurer 1..8 caractères sur chaque axe.

Extrait, après création de votre asset :

    const level = c64.assets.loadMap("assets/mon-niveau.json");
    c64.screen.setup();
    c64.charset.use(level.charset, { address: 0x3000 });
    c64.map.draw(level, { x: 0, y: 0 });

Les chemins sont relatifs au source. drawViewport affiche une fenêtre :
sourceX/sourceY, width/height, x/y. Les dimensions sont constantes ; les positions
source acceptent des références numériques selon la fonction utilisée.
Pour drawViewport, sourceX/sourceY et width/height sont en tuiles ; x/y sont
en caractères écran. La fenêtre occupe donc width × tileWidth caractères de
large, et height × tileHeight de haut. Une map conserve une taille de fenêtre
et une position d'affichage définies pour la compilation.
Les exports récents conservent les glyphes système 0..63 et placent les dessins
personnalisés à partir de 64. Vérifiez les codes des anciens charsets.

Tuiles et conversions
--------------------
    let tuile = 0;
    level.map(3, 4).load(tuile);
    level.map(3, 4).set(2);
    level.map.redraw();
    if (level.map(3, 4).isSolid()) { ... }

load écrit dans une variable de sortie ; set modifie la grille ; redraw rafraîchit
la map, pas une cellule passée en argument. La cellule propose aussi eq(valeur),
ne(valeur), hasCollision(code). Ce sont des accès
spécialisés à une ressource ; load n'est pas un retour numérique ordinaire.
map.tileAt/setTile sont les accès équivalents via le module map.

    let tileX = 0;
    let tileY = 0;
    c64.map.pixelToTile(level, { x: 80, y: 40 }, { x: tileX, y: tileY });

pixelToTile, tileToPixel, characterToTile, tileToCharacter utilisent des variables
de sortie. Choisissez des word pour les positions monde dépassant 255.
map.object(level, "player") retrouve un objet décrit dans le niveau ; objects
sélectionne plusieurs descriptions par identifiant/type. Ces descriptions sont
connues à la compilation ; spawn les transforme en entités actives.


16. SCROLL, CAMÉRA ET INTERFACE FIXE
===================================
Le scroller combine le défilement fin du VIC-II et les déplacements de caractères.
Commencez par une petite fenêtre et une vitesse d'un ou deux pixels.
Le scroll fin demande actuellement des tuiles de 1 × 1 caractère et un seul
scroller raster par programme. La fenêtre doit rester dans les colonnes 1..38 :
x >= 1 et x + width <= 39, avec une largeur d'au moins deux caractères.

Extrait avec level chargé précédemment :

    const camera = c64.map.scroller(level, {
      sourceX: 0, sourceY: 0, width: 36,
      x: 2, y: 1, panel: { bottom: 5 }
    });

Appelez camera.draw() dans init, puis dans update :

    joystick.scroll(camera, 2);

Cette abstraction lit les directions ; elle ne crée pas un personnage ni sa
physique. Les méthodes séparées sont left/right/up/down(vitesse). Une vitesse
constante va de 1 à 8 ; une vitesse calculée doit rester dans 0..8, où 0 ne bouge
pas. Les directions opposées sont traitées successivement ; une diagonale peut
faire avancer les deux axes.

Le panneau réserve des lignes d'interface : { bottom: nombre }, { top: nombre },
"bottom" ou "top". Le scroll vertical a des contraintes supplémentaires et
nécessite le panneau inférieur prévu par le moteur. Reprenez d'abord une
configuration validée. Affichez le HUD avec printAt/printNumber : un POKE brut
peut ignorer les ajustements d'adressage liés au défilement.
Avec un nombre de lignes explicite, le moteur calcule la hauteur de la fenêtre
à partir de la place laissée au panneau ; inutile d'indiquer aussi height.
Le scroll vertical réserve en outre une ligne de transition en bas de la
fenêtre. Le compilateur refuse les directions dépassant le budget prévu :
réduisez alors la fenêtre au lieu de contourner le diagnostic.

Suivi et projection
-------------------
    camera.follow(player, {
      axis: "x", deadZone: { x: 104, y: 48, width: 96, height: 48 },
      maxSpeed: 2, cullingMargin: { x: 24, y: 21 }
    });
    camera.project(enemy, { cullingMargin: { x: 24, y: 21 } });

La zone morte laisse bouger le personnage avant de déplacer la caméra. axis
accepte x, y ou both selon le scroller. offsetX/offsetY ajustent le cadrage.
follow projette aussi le joueur ; project convertit la position des autres
entités et gère leur marge de visibilité. Votre logique décide si un ennemi
hors champ continue à évoluer dans le monde.
Le moteur planifie copies de caractères/couleurs et présentation des sprites.
Ne remplacez pas ce timing par des copies manuelles. Grande fenêtre, musique
et sprites consomment ensemble le budget disponible : testez la combinaison.

Pour essayer sans créer un niveau, copiez
node_modules/js-c64/examples/assets/maze-room.json vers assets/maze-room.json. Voici une fenêtre adaptée à cette petite map :

--- Programme complet : 11-scroll ---
"use c64";
import { c64 } from "js-c64";

const room = c64.assets.loadMap("assets/maze-room.json");
const joystick = c64.input.joystick(2);
const camera = c64.map.scroller(room, {
  width: 12, height: 8, x: 4, y: 5, panel: "bottom"
});
function init() {
  c64.screen.setup();
  c64.charset.use(room.charset);
  c64.printAt(1, 20, "JOYSTICK 2 : SCROLL");
  camera.draw();
}
function update() {
  joystick.scroll(camera, joystick.fire() ? 4 : 1);
}
c64.game.run({ init, update });
--- Fin du programme ---


17. ENTITÉS, COLLISIONS DE TERRAIN ET PLATFORMER
===============================================
Une entité associe un objet de map, un sprite, une position monde et les tests
de terrain. Extrait basé sur les assets de natural-platformer.js :

    const collisions = { 1: "solid", 2: "danger", 3: "exit", 4: "ladder" };
    const player = c64.map.spawn(level, "player", {
      sprite: 0, maxCollisionSpeed: 8, collisionBehaviors: collisions
    });

Chargez auparavant les assets sprites référencés par le niveau. Le numéro
appartient aux données de collision ; le comportement indique son interprétation.
platform et passable existent également. ladder permet un test, pas des commandes
d'escalade automatiques.

Extrait de update :

    player.velocityX = 0;
    if (joystick.left()) player.velocityX = -2;
    if (joystick.right()) player.velocityX = 2;
    if (player.isOnGround() && joystick.firePressed()) player.jump(8);
    player.velocityY += 1;
    player.moveAndCollide();
    camera.follow(player, { axis: "x", maxSpeed: 2 });

velocityY += 1 applique la gravité. moveAndCollide résout les contacts selon
les limites configurées. Accordez maxCollisionSpeed au saut et aux vitesses ;
un déplacement arbitrairement grand peut dépasser les contraintes prévues.

État et actions
---------------
  worldX/worldY             positions du monde sur 16 bits
  screenX/screenY           coordonnées projetées
  velocityX/velocityY       vitesses interprétées par le moteur
  isOnGround()/isActive()   état de déplacement/activation
  isOnDanger()/isOnLadder()/isAtExit()
  setWorldPosition(x,y), setVelocity(vx,vy), moveAndCollide(), jump(force)
  project(options), enable(), disable(), respawn("identifiant")
  collides(autreEntite), play("nomAnimation")
  pauseAnimation(), resumeAnimation()

Le niveau peut fournir les animations. Choisissez-les avec if/else et gardez
un booléen de direction pour éviter les comparaisons signées ambiguës.
spawnAll crée plusieurs entités avec firstSprite et des options communes, mais
le tableau de handles est statique : ce n'est pas un tableau typé à indice
dynamique. Commencez avec des entités nommées ou des indices constants.
Pour une pièce ramassée, mémorisez collected, désactivez l'entité et augmentez
le score une seule fois. respawn remet à un point nommé ; votre jeu décide
quelles autres données sont conservées après une mort.


18. PLUSIEURS NIVEAUX ET CHARGEMENT SUR DISQUE
============================================
Un PRG inline embarque ses ressources. Un D64 peut séparer programme et assets :

    npx c64js build main.js -o dist/jeu.d64 --assets disk --device 8

Le format d64 choisit les assets disque par défaut. --disk-name et --program-name
règlent les noms. Montez le D64 dans l'émulateur ; depuis BASIC :

    LOAD"*",8,1
    RUN

Extrait d'organisation :

    const level1 = c64.assets.loadMap("assets/niveau1.json");
    const level2 = c64.assets.loadMap("assets/niveau2.json");

    // Dans init :
    level1.activate({ draw: true });

    // Dans update :
    if (joystick.firePressed()) {
      if (level1.isActive()) level2.activate({ draw: true });
      else level1.activate({ draw: true });
    }

activate accepte aussi { draw: { x: 0, y: 0 }, sprites: [dessin] }. Le changement
est appliqué à une frontière de frame ; ne demandez pas plusieurs activations
en supposant que isActive change immédiatement pendant la même étape.
loadSprite(..., { resident: false }) prépare un sprite chargé avec son niveau.
Des ressources mutuellement exclusives peuvent partager de la mémoire ; cela
ne rend pas deux maps accessibles simultanément dans la même zone.
Le chargement KERNAL est bloquant : prévoyez une transition, pas un scroll
continu pendant la lecture. Les assets générés sont des fichiers PRG adaptés
au chargement du moteur. Inspectez les fichiers et réservations avec --report.

19. COMPILER, EXAMINER ET OPTIMISER UN PROGRAMME
==============================================
    npx c64js build main.js -o dist/jeu.prg
    npx c64js build main.js -o dist/jeu.asm
    npx c64js build main.js -o dist/jeu.lst
    npx c64js build main.js -o dist/jeu.bin
    npx c64js build main.js -o dist/jeu.bas
    npx c64js build main.js -o dist/jeu.d64

  prg   programme avec adresse de chargement et lanceur de la compilation
  bin   binaire brut pour une intégration maîtrisée
  asm   représentation assembleur
  lst   listing avec adresses et octets
  data  BASIC/DATA, extension habituelle .bas
  d64   image de disquette avec programme et ressources

L'extension sélectionne le format ; --format permet de le préciser. --sys règle
l'adresse demandée au lanceur selon votre configuration ; program.start est le
moyen lisible de fixer le placement dans le source. Dans les options, écrivez
un nombre décimal ou 0x4000, pas $4000.

    npx c64js build main.js -o dist/jeu.prg --opt balanced --map dist/symboles.json --report dist/rapport.json

--opt accepte size, speed, balanced. Ces profils choisissent les stratégies
prévues par le moteur, notamment pour les ressources ; comparez les résultats
pour votre jeu. --map exporte les symboles ; --report décrit ressources,
réservations et décisions, y compris les optimisations du compilateur.

Les optimisations du compilateur sont actives par défaut : réutilisation prudente
des temporaires, suppression de copies inutiles et reconnaissance de certains
remplissages de tableaux. Le compilateur respecte les limites entre fonctions,
API et interruptions. Écrivez d'abord clairement : tableau.fill(0) exprime
mieux un remplissage qu'une manipulation manuelle de pointeurs.

Validation conseillée
---------------------
  1. Compilez ; corrigez types, constantes et conflits de placement.
  2. Lancez le PRG : affichage, commandes, collisions, redémarrage.
  3. Testez les limites : bords, 255/256, tableau plein, vie zéro.
  4. Ajoutez musique, scroll et sprites ensemble et observez leur timing.
  5. Examinez le listing et le rapport si taille ou fluidité posent problème.
  6. Vérifiez PAL et NTSC si vous ciblez les deux.

Compiler prouve que le source est accepté et assemblé, pas que chaque effet
visuel ou sonore est correct. Un microbenchmark ne garantit pas la fluidité
de tous les niveaux d'un jeu.

21. DÉPANNAGE ET BONNES HABITUDES
================================
« Cela fonctionne en JS, pas dans js-c64. »
  Vérifiez le sous-ensemble du chapitre 3 : pas de Math.random, setInterval,
  console.log ou chaînes dynamiques. Les ressources/options sont souvent fixes.

« Ma variable revient à zéro ; ma boucle ne finit jamais. »
  Un octet déborde à 256. Élargissez avant le calcul, y compris les compteurs.

« Le programme reste figé. »
  Cherchez while infini, waitKey dans update, son bloquant ou frame trop chargée.

« Les lettres deviennent des dessins. »
  Vérifiez le charset, les codes écran et les glyphes système réservés.

« Un dessin HR recolore son voisin. »
  Deux couleurs seulement par cellule de 8 × 8 pixels : chapitre 13.

« Ma forme a une mauvaise taille. »
  Vérifiez la largeur des calculs, puis les unités : cases, pixels, coordonnées
  de sprites. Examinez le listing si nécessaire.

« Des sprites disparaissent ou clignotent. »
  Vérifiez leur activation, coordonnées, pointeurs, banque VIC et recouvrement
  sur la même ligne raster.

« Le scroll laisse des traces. »
  Reprenez une configuration validée. Vérifiez panneau, charge de la frame et
  écritures directes concurrençant le moteur.

« Le son coupe une note. »
  Réservez une voix aux effets ; un nouvel effet remplace le précédent.

« Je manque de mémoire. »
  Examinez --report et --map. Réduisez les ressources, partagez les données
  identiques ou répartissez les niveaux sur disque ; ne déplacez pas une zone
  au hasard dans la RAM du moteur.

« Les conditions ou les variables ne sont pas compilées comme prévu. »
  Vérifiez la présence de "use c64" au début du fichier et compilez avec
  « npx c64js build ». « npm ls js-c64 » affiche la version installée ; ce guide
  correspond à la 1.1.0.

Gardez sources, JSON et commandes de construction dans Git. Les PRG ne remplacent
pas les sources. Après une correction du compilateur, reconstruisez avant de
comparer le comportement dans l'émulateur.

Cas spécialisés et compatibilité

conditions, boucles et fonctions directement en JavaScript.


23. API DE COMPILATION ET OUTILS POUR LES DÉVELOPPEURS
====================================================
Cette partie concerne un script Node.js sur votre ordinateur, pas un programme
C64. N'y ajoutez pas "use c64".

    import { writeFile } from "node:fs/promises";
    import { compileFile } from "js-c64";

    const result = await compileFile("main.js", { opt: "balanced" });
    await writeFile("jeu.prg", result.prgBytes);
    console.log(result.assetReport);

compileFile charge un fichier ; compileJsToC64Outputs compile un texte. Le
résultat donne bytes, prgBytes, asmText, listingText, symbols, basicText,
assetReport et diskFiles. Options : opt, assets, device, placement du code.
naturalOptimizations: false permet une comparaison diagnostique sans cette
passe ; ce n'est pas nécessaire pour programmer un jeu normalement.

Autres exports :
  compileJsToBasicData       représentation BASIC/DATA
  compileInstructions       compilation d'une représentation intermédiaire
  Assembler6502             construction directe d'assembleur
  createBasicSysStub        lanceur BASIC
  createPrg/createRawBinary emballage des octets assemblés
  createBasicDataProgram/exportBasicData
  loadMapAsset/normalizeMapAsset/expandMapAsset
  loadSpriteAsset/normalizeSpriteAsset
  createD64/d64SectorOffset/D64_SIZE

Sous-chemins npm : js-c64/assembler, /compiler, /assets, /d64 et /irq/raster.
Consultez les types et exports pour écrire un outil de construction personnalisé.
Dans le dépôt :

    npm test
    npm run build:demos
    npm run package:check
    npm run release:check

release:check reconstruit et valide les artefacts de livraison ; il n'est pas
nécessaire après chaque modification d'un jeu. docs, scripts, test et studio
graphique appartiennent au dépôt. Le paquet npm contient compilateur, types,
schémas, exemples et assets, README, changelog et ce guide.
Pour poursuivre, consultez les exemples et le détail des changements
dans CHANGELOG.md. README.md présente les versions et les points d'entrée.
